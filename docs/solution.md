# 同行 / 在路上（微信小程序）V2 方案

## 1. 产品目标

围绕“在路上”场景，连接同时间、同路线、同交通工具的人，形成垂直信息流和即时同行社交。

## 2. MVP 功能范围

### 2.1 已落地（本仓库 V2）

1. 微信登录（支持 mock / real code2Session 双模式）
2. 行程状态更新（交通工具、路线、出发地/目的地、阶段）
3. 广场发帖（支持匿名 + 媒体附件）
4. 帖子点赞、帖子举报
5. 好友申请/同意/拒绝
6. 群组创建、发现、加入、离开、解散
7. 群消息（支持匿名）
8. WebSocket 实时群消息推送
9. 媒体上传（本地 / COS）
10. 审核管道（帖子、群组、群消息、媒体）
11. 管理端接口（举报处理、封禁用户、解散群、内容审核）

### 2.2 下一阶段建议

1. 管理后台 UI（目前已具备管理 API）
2. 同路推荐（同航班/同车次/同目的地）
3. 群组生命周期自动归档任务
4. 订阅消息（开车/登机提醒、群消息提醒）
5. 行程真实性校验（航班/车次数据源）

## 3. 架构方案

## 3.1 客户端

- 技术：微信小程序原生（JS + WXML + WXSS）
- 页面：广场、发布、群组、群聊、我的
- 能力：登录态持久化、API 请求封装、媒体上传、实时聊天

## 3.2 服务端

- 技术：Node.js + Express
- 能力：
  - 登录鉴权（Bearer Token + code2Session 接口适配）
  - 行程/帖子/好友/群组业务接口
  - 媒体上传与存储抽象（local/COS）
  - 内容审核服务（本地词库 + 微信审核接口）
  - WebSocket 群聊通道
  - 管理端审核接口
  - 数据库自动初始化

## 3.3 数据库

- 本地可运行：SQLite（开发效率高、零依赖）
- 生产推荐：PostgreSQL + Redis
  - PostgreSQL：业务主数据
  - Redis：会话缓存、频控、热门排序、临时群索引

仓库中提供了 PostgreSQL 参考建表脚本：`server/sql/schema-postgres.sql`。

## 4. 数据隐私与合规设计

1. 匿名内容仅前台匿名，后台保留发布者映射
2. 默认不展示精确位置，仅展示行程信息（出发地/目的地/路线）
3. 举报机制闭环（举报记录 -> 审核处理）
4. 群组/动态/消息/媒体都具备审核状态字段（approved/review/rejected）

## 5. 生产部署建议

## 5.1 推荐部署拓扑

1. 微信小程序前端：微信托管/静态托管
2. API 服务：容器（腾讯云 CFS/CVM/K8s 均可）
3. DB：腾讯云 PostgreSQL
4. 缓存：腾讯云 Redis
5. 媒体：COS + CDN

## 5.2 必备工程能力

1. API 网关限流（按 IP + 用户）
2. 审计日志（登录、发帖、加群、解散）
3. 监控告警（5xx、延迟、慢查询、审核失败率）
4. 敏感词和多媒体审核（机审 + 人审）

## 6. 核心风险与控制

1. **匿名滥用风险**：必须有举报、封禁、审核后台
2. **同路隐私风险**：避免展示实时精确定位
3. **垃圾群风险**：群有效期与自动归档机制
4. **伪造行程风险**：引入航班/车次校验接口（后续）
